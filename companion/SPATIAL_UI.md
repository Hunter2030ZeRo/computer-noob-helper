# 앱 내부 3DoF 안내

컴맹도우미의 **안경 안내 화면**에만 적용됩니다. YodaOS-Sprite 런처, 다른 앱, 시스템 창의 위치는 바꾸지 않습니다. 앱을 열면 작은 디스플레이용 HUD가 바로 나타납니다. `메뉴 → 연결 · 화면 설정 → 고급 설정`에서 3DoF를 끄면 같은 HUD를 화면 고정 방식으로 사용합니다.

## 작은 화면용 HUD와 자동 카메라

카메라 ID 입력과 별도 시작 절차를 없앴습니다. 최초 실행의 Android 카메라 권한을 허용하면 후면 → 외장 → 기타 → 전면 순서로 카메라를 자동 선택합니다. 바인딩에 실패하면 다음 후보를 시도합니다. CameraX의 ImageAnalysis만 연결하여 미리보기 창 없이 인식합니다. 권한 거부나 연결 실패 시 메뉴의 다시 연결로 재시도합니다. 앱은 전경에서만 카메라를 사용하며 사용자가 일시 정지하면 해당 실행 중에는 자동으로 다시 켜지지 않습니다.

기본 HUD는 검은(광학적으로 꺼진) 배경, 단색 녹색 선, 주변부 상태 표시, 관심 영역 모서리 브래킷으로 구성합니다. 시야 중앙에는 작은 열린 기준 표시만 남기고 안내는 아래쪽에 둡니다. 가짜 배터리/스캔 수치/모델 신뢰도는 표시하지 않습니다. 영상이 나오는 스마트폰용 미리보기, 텍스트 입력칸, 보정 폼은 기본 HUD에 없습니다.

폰트를 통째로 축소하지 않고 실제 화면 폭에 맞춰 안내를 **2줄(높이 360dp 미만) 또는 3줄씩** 페이지로 나눕니다. 말하기/메뉴가 기본 조작이며 긴 안내 또는 여러 단계가 있을 때만 이전/다음 조작을 추가합니다. 모든 조작의 최소 높이는 48dp입니다. 전경 설정 및 보정은 메뉴에 모았습니다. 개발용 Compose preview는 320×426dp와 426×280dp를 제공하며, 이는 실제 RV101 밀도/FOV의 확정값이 아닙니다.

앱 진입으로 시작되는 것은 로컬 카메라 인식입니다. 서버 전송과 연속 공유는 사용자의 요청으로 시작합니다. 에이전트 주소/토큰은 기존처럼 연결 설정에서 지정합니다.

## 착용자 변경과 손 조작

[MediaPipe 제스처·착용자 변경·광학 안전 여백 안내](GESTURES_AND_WEAR.md)가 최신 동작을 설명합니다. 반복 드리프트 복귀를 막기 위해 시간 기반 자동 복귀와 펼친 손 리셋을 제거했습니다. 항상 보이는 ↺ 버튼·메뉴 UI 리셋·착용 이벤트로 재설정합니다.

## 표시 동작

- 문제 안내 카드: 화면 진입 시 바라보는 방향에 고정합니다. 센서의 yaw/pitch/roll을 반영하여 네 모서리를 다시 투영합니다. 글자까지 원근 변환하므로 기울임에 따라 카드도 회전합니다.
- 관심 영역: 에이전트가 전송된 이미지에서 지정한 영역을 테두리와 라벨로 표시합니다. 응답을 받은 순간의 방향이 아니라 **그 이미지의 촬영 자세**를 사용합니다. 모델이 반환하는 영역은 대략적인 시각 주석이며 모델 내부 attention이나 시선 추적값이 아닙니다.
- 시야 밖이나 뒤쪽으로 넘어간 요소는 숨깁니다. 잠시 고개를 돌렸다가 원래 방향으로 돌아오면 다시 나타납니다. 시야 밖에서는 ↺ 버튼으로 안내 카드를 가져올 수 있습니다.
- `정면 재설정`: 문제 카드만 지금 보는 방향으로 옮깁니다. 이미지의 관심 영역을 임의로 옮기지 않습니다.
- 음성/이전/다음/중지 버튼은 언제든 조작할 수 있도록 화면에 고정합니다. 긴 안내는 페이지로 나누어 모두 읽을 수 있으며, 전체 응답도 설정 화면에서 볼 수 있습니다.
- 앱이 일시 정지되면 센서를 해제합니다. 재개/화면 회전 때 추적 세대를 바꾸어 이전 세대의 관심 영역은 숨깁니다. 음성 인식 화면에서 복귀한 직후의 오래된 프레임도 이에 해당합니다. 최신 프레임을 다시 전송하세요.
- 센서 값이 250ms 이상 갱신되지 않으면 추적 불가를 표시하고 일반 화면 고정 안내로 임시 전환합니다.

## 설정 및 정합

1. 앱을 안경 자체에서 실행하고 최초 카메라 권한을 허용합니다. 이후에는 자동 연결됩니다.
2. 메뉴의 연결 · 화면 설정 → 고급 설정에서 회전 센서 이름과 `마지막 프레임: 촬영 자세 동기화됨` 상태를 확인합니다.
3. 디스플레이 가로/세로 FOV, **회전 보정된 전송 이미지**의 카메라 가로/세로 FOV, 카메라 yaw/pitch 오프셋을 실측값으로 입력하고 `실측 보정값 적용`을 누릅니다.
4. 이미지 첨부를 켜고 문제를 전송한 뒤 안경 안내 화면으로 이동합니다.
5. 동일한 위치에서 좌우/상하 회전과 머리 기울임을 시험하고 영역이 보이는 대상과 정합하는지 확인합니다.

기본값 `display=30×22°, camera=60×45°, offset=0°`는 개발용 예시이며 **RV101의 보정값이 아닙니다**. 보정 적용 전에는 관심 영역을 표시하지 않습니다. 보정은 앱 재생성 시 초기화됩니다. 가로/세로 시야각은 대각 시야각과 다릅니다. 화면 전체를 광학 viewport로 가정하며, 렌즈 왜곡/비대칭 투영/카메라 roll 장착 오차/눈과 카메라 사이 거리 보정은 아직 포함하지 않습니다. 현 구현은 회전 보정된 카메라와 디스플레이의 축이 대체로 정렬된 구성을 전제로 합니다. 실기기에서 이 전제가 다르면 CXR-S 장치별 보정과 렌더링 경로를 연결해야 합니다.

## 자세와 시간

`HeadTracker`는 Android의 ROTATION_VECTOR를 우선 사용하고 GAME_ROTATION_VECTOR로 대체합니다. 디스플레이 회전에 맞춰 좌표축을 변환하며, 최근 240개 센서 자세를 보관합니다. Camera2가 `SENSOR_INFO_TIMESTAMP_SOURCE_REALTIME`을 보고하는 카메라에 대해서만 프레임 시각과 50ms 이내인 센서 자세를 연결합니다. 동기화되지 않은 자세, 전면 카메라, 카메라 시작 후 변경된 화면 회전에는 관심 영역 표시를 하지 않습니다. 자세는 로컬 프레임에 붙고 모델에 보낼 필요는 없습니다.

추적 세대별 world ray를 저장하고 현재 회전 행렬의 역행렬로 화면 방향에 투영합니다. Euler 각도 차이로 픽셀 위치를 단순 이동하는 방식은 사용하지 않습니다. GAME_ROTATION_VECTOR의 yaw는 시간이 지나며 드리프트할 수 있어 정면 재설정이나 새 프레임 전송이 필요합니다.

## 서버 응답 확장

기존 완료 응답에 다음 필드를 추가했습니다. 서버가 없거나 기존 버전이면 문제 카드만 표시됩니다.

```json
{
  "focus_regions": [
    {"label": "오류 메시지", "box": [0.15, 0.2, 0.7, 0.45]}
  ]
}
```

`box`는 전송한 JPEG의 `[left, top, right, bottom]`, 범위는 0..1입니다. 서버와 앱이 각각 검증하며 최대 4개만 사용합니다. 이미지가 없으면 서버는 빈 배열을 반환합니다. 새 요청을 시작하면 이전 관심 영역을 지웁니다. 잘못된 좌표는 무시합니다.

## 한계와 검증

이는 **회전 방향 고정(3DoF)**입니다. 사용자의 평행 이동, 물체의 이동, 모니터 화면 스크롤을 추적하지 않습니다. 실제 물체에 지속적으로 붙는 6DoF SLAM/visual tracking은 별도 구현이 필요합니다. 자세 예측/late latching/광학 왜곡 보정도 없으므로 실기기의 지연과 광학 정합을 검증해야 합니다. Android에 회전 벡터 센서가 노출되지 않는 RV101 펌웨어에서는 CXR-S IMU 연동 또는 센서 융합 경로가 추가로 필요합니다.

단위 테스트는 원래 방향으로 복귀, yaw/pitch/roll, 촬영 자세 기반 지연 응답, 뒤쪽/시야 밖 제거, 추적 세대 변경, 카메라 장착 오프셋 및 잘못된 FOV/영역을 검사합니다. PC 테스트는 모델 관심 영역의 범위 및 이미지 없는 응답을 검증합니다. 빌드/테스트 통과가 실제 안경의 광학 고정 성능을 보증하지는 않습니다.

참고: [Android 회전 센서](https://developer.android.com/develop/sensors-and-location/sensors/sensors_position), [센서 좌표 변환](https://developer.android.com/reference/android/hardware/SensorManager), [카메라 timestamp source](https://developer.android.com/reference/android/hardware/camera2/CameraCharacteristics#SENSOR_INFO_TIMESTAMP_SOURCE), [Rokid 공식 CXR-S 소개](https://open.rokid.com/).

소형 HUD 계측 테스트(`HudSurfaceTest`)는 폼 없는 기본 화면, 메뉴의 카메라 조작, 낮은 화면의 2줄 페이지 이동을 검사합니다. 연결된 Android 기기/에뮬레이터가 없는 환경에서는 테스트 APK 빌드까지만 가능하며, 광학 가독성과 센서 정합은 안경에서 확인해야 합니다.
