# 중앙 고정형 HUD 업데이트

안내 패널과 상태·버튼은 IMU와 무관한 화면 고정형입니다. 주요 콘텐츠의 좌우 여백은 18%, 세로 화면의 상하 여백은 22%로 중앙에 모았습니다. 작은 가로 화면은 상하 13%로 조정하고 안내는 페이지 단위로 유지합니다. 얇은 녹색 계기선·코너 브래킷을 사용합니다.

메뉴는 Android Dialog 창입니다. 메뉴가 열린 동안 배경 말하기·리셋·메뉴·페이지 버튼은 비활성화되어 터치패드 포커스를 받지 않습니다. 메뉴 내부에서 포커스를 이동하며 뒤로 가기/닫기로 돌아오면 메인 메뉴 버튼에 포커스를 복구합니다. 바깥쪽 클릭으로 닫거나 배경 버튼을 실행하지 않습니다. 손 관절 진단은 메뉴를 덮지 않습니다.

기존 3DoF 안내 카드 투영은 제거했습니다. 고급 설정의 회전 보정은 실험적인 관심 영역에만 적용되고 기본 꺼짐입니다. 일반 HUD에서는 회전 센서 구독과 렌더링 폴링도 하지 않습니다. UI 리셋은 안내의 첫 페이지로 돌아가고 이전 관심 영역을 비웁니다.

아래 이전 광학 여백 설명보다 이 업데이트의 수치와 동작이 우선합니다.

# 손 조작과 착용자 변경

## 손 관절과 제스처

MediaPipe Hand Landmarker 0.10.35와 공식 float16/revision 1 모델을 APK에 포함했습니다. 안경 카메라의 컬러 영상을 긴 변 최대 512px로 줄여 한 손의 21개 관절을 추론합니다. 손 영상과 관절은 제스처 처리용으로 서버에 보내지 않습니다. 기존의 시야 공유 요청은 별도로 유지됩니다.

기본으로 켜져 있으며 HUD 메뉴 → 연결 · 화면 설정의 `손 제스처 조작`에서 끌 수 있습니다. 손을 안경의 카메라 시야 안에 보여 주세요. 카메라 범위 밖의 손은 인식할 수 없습니다.

| 동작 | 기본 HUD | 메뉴가 열린 상태 |
| --- | --- | --- |
| 엄지·검지 핀치 최소 0.25초·2프레임 | 메뉴 열기 | 강조된 항목 선택 |
| 손날을 세우고 오른쪽으로 넘기기 | 다음 페이지/단계 | 다음 메뉴 항목 |
| 손날을 세우고 왼쪽으로 넘기기 | 이전 페이지/단계 | 이전 메뉴 항목 |
| 화면의 ↺ 버튼 | UI 리셋 | 정면 복귀 후 메뉴 닫기 |

메뉴는 `말하기 / UI 리셋 / 시야 일시 정지·재연결 / 연속 공유 / 연결·화면 설정 / 닫기`입니다. 손으로 선택된 항목이 사라지지 않도록 3개씩 표시합니다. 터치/기존 버튼 조작도 사용할 수 있습니다. 카메라를 정지하면 손 조작도 멈추므로 재연결에는 기존 입력 인터페이스가 필요합니다.

손 크기에 따라 핀치 거리를 정규화하며 손을 놓아야 다음 입력을 받습니다. 최소 0.9초의 재입력 간격, 0.7초 이상 프레임 공백 시 진행 중인 동작 리셋, 늦게 도착한 결과 무시를 적용합니다. 빠른 움직임·조명·가려짐·카메라 방향 변화에 따른 오인식은 실기기에서 임계값 조정이 필요합니다. 이 규칙은 범용 학습 제스처 분류기가 아니라 MediaPipe 관절 좌표 위에 구현한 시간 기반 판정입니다.

손 추론의 100ms 간격 제한을 제거했습니다. 이전 추론이 끝나면 다음 카메라 프레임을 즉시 받아 처리하며, 처리 중에는 새 손 프레임을 버립니다. 색 변환은 stride를 검증하는 JNI C++ 코드에서 수행합니다. 최근 손이 검출됐으면 OCR 간격을 최소 5초로 늘려 CPU 경쟁을 줄입니다. CPU의 별도 worker에서 VIDEO 모드로 추론합니다. OCR은 별도 작업 큐에서 복사본을 처리하므로 인식 완료를 기다리며 카메라 프레임을 점유하지 않습니다. 실제 주기는 RV101 성능에 영향을 받습니다. 백그라운드·설정 화면·탈착 상태에서는 제스처 명령을 받지 않습니다. 설정에서 손 인식 진단을 켜면 로컬 영상·관절·처리 지연·핀치 상태만 표시합니다. 오류가 나면 기본 입력을 유지하고 손 인식 오류를 표시합니다. 모델 재초기화는 카메라 재연결로 수행합니다.

## 안경을 다른 사람에게 넘겼을 때

Rokid 공식 문서의 다음 상태 방송을 전경에서 구독합니다.

- `com.rokid.sprite.ACTION_TAKE_STATUS_CHANGED`, extra `glasses_take_state`: 문자열 `1` 착용 / `0` 탈착
- `com.rokid.sprite.ACTION_LEG_STATUS_CHANGED`, extra `glasses_leg_state`: 문자열 `1` 펼침 / `0` 접힘

착용/펼침 알림을 받으면 안내 카드의 기준 방향을 다시 잡습니다. 탈착/접힘은 연속 공유를 끄고 제스처 입력을 중지합니다. 이전의 관심 영역과 촬영 자세는 폐기합니다. 다시 착용해도 연속 공유는 자동으로 켜지지 않습니다. 이 이벤트는 사람의 신원을 인식하지 않으며 계정이나 기존 안내 문장을 삭제하지 않습니다.

**시야 밖 2.5초 자동 복귀와 펼친 손 유지 리셋을 제거했습니다.** 드리프트 때문에 반복 복귀하는 문제를 피하기 위해 화면에 항상 남는 `↺` 버튼 또는 메뉴의 `UI 리셋`으로 정면을 다시 잡습니다. 착용 이벤트와 앱 복귀 시 초기화는 유지합니다. 센서가 없으면 화면 고정 안내를 사용합니다.

리셋은 이전 관심 영역도 지웁니다. 새로운 관심 영역은 새 시야를 에이전트에 전송해 받아야 합니다. 자북 보정 ROTATION_VECTOR를 우선 사용하고 없으면 GAME_ROTATION_VECTOR로 대체합니다. 전자는 주변 자기장에 영향을 받을 수 있고 후자는 yaw 드리프트가 남을 수 있습니다. 이번 변경이 실기기 드리프트 제거를 보장하지는 않습니다.

## 실제 시야의 손 관절 오버레이

중앙 고정형 HUD에서는 손 관절 오버레이를 진단 옵션으로 분리하여 기본으로 끕니다. 설정의 `HUD 손 관절 오버레이`로 끌 수 있습니다. MediaPipe의 회전 보정된 카메라 정규화 좌표를 카메라 FOV → 장착 yaw/pitch → 디스플레이 FOV로 투영하여 21개 관절과 연결선을 그립니다. 핀치 판정용 종횡비 보정 좌표와는 별도입니다. 손은 움직이므로 공간 앵커에 고정하지 않습니다.

- 녹색 관절: 현재 검출된 손. 상태에 관절 수·추론 지연·핀치 유지/해제 상태를 표시합니다.
- 흰색 관절 점멸과 판정 이름: 핀치 또는 좌우 이동을 판정했습니다. 비활성 메뉴 항목 등에서는 실제 명령 실행과 다를 수 있습니다.
- 손 미검출: 새 프레임에 손이 없으면 즉시 관절을 지웁니다. 마지막 입력 프레임이 700ms 이상 오래되면 관절 표시도 만료됩니다.
- 관절이 실제 손과 어긋남: 임시 FOV 기본값일 수 있습니다. 고급 설정의 디스플레이/회전 보정 카메라 FOV와 yaw/pitch를 조정합니다. 보정 후에도 카메라-눈 사이 위치 차이, 손 깊이, 렌즈 왜곡, 처리 지연과 움직임에 따른 오차는 남습니다. 정확한 3D 손 정합이나 물리적 접촉 판정은 아닙니다.

관절이 화면 밖으로 나가더라도 화면 가장자리로 강제로 모으지 않습니다. 검출 수는 21인데 선이 안 보이면 카메라에는 손이 있지만 디스플레이 시야 밖으로 투영되는지도 확인하세요. 설정의 카메라 영상 진단과 비교할 수 있습니다. HUD에서는 기존 제스처 명령도 계속 실행되며, 설정의 영상 진단 화면에서는 명령을 실행하지 않습니다.

## 케이블 없이 확인하기

1. 메뉴 → 연결·화면 설정 → **손 인식 진단 화면**: 실제 추론에 들어가는 컬러 영상과 녹색 21관절을 봅니다. 관절 0은 검출 실패, 관절 21인데 명령이 안 되면 자세·유지·해제 조건 또는 처리 지연을 확인합니다. 650ms 이상 걸린 결과는 입력으로 실행하지 않습니다. 450ms부터 지연 경고를 표시하며 변환·추론·프레임 간격을 각각 표시합니다. 진단 영상은 초당 최대 1회 갱신하며 서버로 전송하지 않습니다.
2. 핀치 후 손을 약 0.2초 펼쳐 해제하고 다시 핀치합니다. 손날 넘기기는 손가락을 펴서 모으고 손을 세운 뒤 참참참처럼 좌우로 넘깁니다. 3개 이상 손가락의 펴짐을 관절 깊이까지 이용해 판정합니다. 영상 폭 14% 이상 이동하면서 같은 방향의 움직임이 두 차례 관측되어야 하며, 판정 창은 최대 1.4초입니다. 인식 후 손을 잠시 내리거나 접었다 다시 펼칩니다. 손목 회전만 하고 손의 위치가 거의 변하지 않으면 판정하지 않습니다. 검출·존재·추적 confidence는 MediaPipe 기본값 0.5를 사용하며 시간 조건으로 명령의 오검출을 억제합니다.
3. 고급 설정 → **15초 입력 진단**: 원시 가속도·자이로와 사용 가능한 두 회전 센서, 카메라 타임스탬프, 최대 10Hz 흑백 영상을 기록합니다. 이때 OCR·손 추론을 잠시 멈추고 연속 전송을 끕니다. 기기 메모리 한도 24MiB/영상 150장/센서 6000개로 제한합니다.
4. **진단 ZIP 저장**으로 Android 파일 저장 화면에서 내보냅니다. 케이블·ADB가 필요하지 않지만 펌웨어에 문서 저장 앱이 있어야 합니다. 저장한 ZIP은 기존 무선 파일 전송 수단으로 PC에 옮깁니다. 파일 저장 앱이 없으면 앱에 오류를 표시하며 자동 업로드하지 않습니다.

ZIP에는 실제 카메라 영상이 포함됩니다. `imu.csv`, `frames.csv`, `metadata.json`, 무회전 PGM 영상이 들어갑니다. 나노초 원본 타임스탬프와 샘플링 배율을 보존하지만 카메라 내부 파라미터·IMU 외부 보정값은 없습니다. **VIO 입력 가능성을 확인하는 진단이며 SLAM/VIO 구현이나 보정 완료 데이터가 아닙니다.**

## 광학 안전 여백과 크기

Rokid의 공개 Glass3 Enterprise 가이드는 480×640 세로 좌표, 중앙 480×400 주 콘텐츠, 상단 약 40px 반사 구간 회피를 안내합니다. RV101 소비자 펌웨어의 정확한 광학 보정값과 동일하다고 간주하지는 않습니다.

이 가이드를 참고하여 HUD의 좌우에 각각 화면 폭 12%, 상단 상태에 높이 14%, 하단 조작에 높이 12.5%의 여백을 적용했습니다. 이는 앱의 보수적인 안전 영역이며 제조사가 지정한 RV101 수치가 아닙니다. 화면 모서리의 COMMA / ASSIST, VISION 문구를 없애고 짧은 한국어 상태로 바꿨습니다. 본문은 14sp/16sp, 조작은 12sp로 조정하며 여전히 2–3줄 페이지 단위로 모든 안내를 읽을 수 있습니다. 설정 화면도 안쪽 여백을 확보했습니다.

## 검증과 남은 확인

- 단위 테스트: 핀치 유지·해제, 중복 방지, 좌우 이동, 펼친 손의 리셋 미발생, 잘못된 관절, 프레임 공백, 핀치 뒤 손 검출 일시 유실과 재입력.
- 계측 테스트: 모델 실제 로딩 및 빈 이미지 추론(`HandModelTest`), 소형 HUD 조작과 페이지 이동(`HudSurfaceTest`).
- APK에 7,819,105바이트 모델을 무압축으로 포함하며 arm64-v8a/armeabi-v7a/x86_64 MediaPipe JNI 포함 여부 확인.
- 연결 기기가 없는 환경에서는 계측 테스트 APK 빌드까지만 수행합니다. 실제 손 인식률/발열/프레임률, RV101의 착용 방송 수신, 광학 가장자리 가독성은 실기기 검증이 필요합니다.
